## 来源、配置及冲突处理

### Claude Opus 5.5

- [官方发布](https://www.anthropic.com/claude-opus-5-5)：默认 max，TB4 取 xhigh；生产防护与任务回退配置逐项标注。AutomationBench 是 Zapier 早期访问测试且不回退，不能与 Google 模型卡里的另一快照混用。
- [AA max/default fallback 对照](https://artificialanalysis.ai/models/comparisons/claude-opus-5-5-vs-grok-4-7)：长文有效推理与窗口规格分开，AA 百分比为页面取整。官方与 AA 的 HLE 结果保留各自协议，不算平均。
- 写作优先看[英文作者实际使用](https://alexmcfarland.substack.com/p/opus-55-is-the-best-model-for-writers)、[中文八轮作品对照](https://finance.sina.com.cn/tech/roll/2026-09-24/doc-iniswmir0727722.shtml)、[中文作者四轮原作](https://blog.adenxie.com.cn/2026/10/14/2026-10-14-gemini-4-argon-vs-claude-opus-5-5-writing-test/)。正反意见都保留。补查 [Lech Mazur 原榜](https://github.com/lechmazur/writing) 显示 high 相对胜率 93%，但不把模型评委当双语人类共识。
- 分析采用 [Plotly/Mila 原始测试](https://plotly.com/blog/introducing-dataanalyticsbench/)，41/43。

### Gemini 4 Argon

- [官方模型卡](https://deepmind.google/models/model-cards/gemini-4-argon/)、[原始方法说明](https://deepmind.google/models/evals-methodology/gemini-4-argon)：最高思考、通常 pass@1，DeepSWE 用 mini-swe；GraphWalks 的 256K–1M 为 200 题、BFS F1，不是所有长文题的正确率。
- ALE 是 binary pass、5 小时和 ALE-Claw。没有将它与 earlier partial 表现直接对比。科学任务 LABBench2 带终端/编程/联网；不标成无工具推理。
- [英文 API 社区一手 RP 测试](https://discuss.ai.google.dev/t/first-test-of-gemini-4-argon-much-better-immersion-but-stricter-with-explicit-adult-roleplay-than-gemini-3-x/189556)、[中文原作者四轮](https://blog.adenxie.com.cn/2026/10/14/2026-10-14-gemini-4-argon-vs-claude-opus-5-5-writing-test/)、[ToneBench high](https://benchmark.towardsai.com/models/gemini-4-argon-high.html)：主观沉浸感、中文 AI 腔与英文频道脚本分开衡量；没有直接把脚本得分变成小说分。
- [Plotly 原始分析测试](https://plotly.com/blog/gemini-4-argon-plotly-data-analytics-bench/) 41/43，隐藏洞察 5/5。

### Grok 4.7

- [官方发布](https://x.ai/news/grok-4-7)、[AA xhigh 当前比较](https://artificialanalysis.ai/models/comparisons/claude-opus-5-5-vs-grok-4-7)：官方 DeepSWE 是 high，其他主表为 xhigh；AA TB4 低于官方结果，框架/快照差异如实保留。
- [英文用户原帖](https://www.reddit.com/r/grok/comments/1wvgw2l/grok_47_seems_for_now_to_be_just_another_mediocre/)、[中文用户原帖](https://linux.do/t/topic/2955324)、[EQ-Bench 长篇原榜](https://eqbench.com/creative_writing_longform)：社区有模型身份及产品路由不确定性，不将全部故障归因基础模型。较高长篇基准作为反证，写作低置信度 A。
- [Plotly 原始对照文](https://plotly.com/blog/muse-wonder-plotly-data-analytics-bench/) 明确 42/43；单题领先不支撑更精细统计排名。

### MiniMax-M3.1-Flash-Preview

- [官方 API 文档](https://platform.minimax.io/docs/guides/text-generation) 确认精确 ID、1M 窗口、五档 effort、默认 max、不可关闭思考。只采用这些明确属于 preview 的信息。
- 新发现 [ModelDial 专属 max 测试](https://modeldial.com/en/models/MiniMax-M3.1-Flash-Preview?axis=overall&config=MiniMax-M3.1-Flash-Preview~max)、[方法](https://modeldial.com/en/method)、[私有任务覆盖说明](https://modeldial.com/en/datasets)：编程和推理已有直接私有量化测试，归 T1 但低置信度。完整题目、轨迹、样本规模未充分公开；其综合 68.45 不作六维整体分，也不称主流基准共识。
- [硅星人作者五项目测试](https://www.woshipm.com/evaluating/6472683.html) 含工具工作流和财报核验；[Coder Liang 一手实测](https://coderliang.com/posts/043c4f0b-fe40-4737-a6d3-76546dab12fe) 含开源修复；[AI 产品狙击手原始反例](https://www.techgogogo.com/2026/09/28/minimax-m3-1-flash-benchmark-report/) 含句子约束/SVG/界面失败。结果有分歧，产品与框架共同影响；不只收录正面样例。
- [英文 MindStudio 测试叙述](https://www.mindstudio.ai/blog/minimax-m3-1-flash-mcode-hands-on) 有 DB2 SQL 小案例，但访问状态说法已与现行文档不同，未用它证明当前可用性或泛化正确率。
- 有财报工具案例，不足以证明百万长度无衰减；长文仍 T3。英中文学检索缺少可复核双语对照，写作仍 T3，不从编程图形创作能力推导小说强度。
